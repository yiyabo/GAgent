# Code Mode（execute_code / Programmatic Tool Calling）

日期：2026-09-24。状态：v1 落地，env 门控默认关。基线：eval/user-journey（044442e1 + 6dbb30a5）。
设计来源：照 NousResearch hermes-agent 的 PTC（Programmatic Tool Calling）抄作业，
最小可用复刻 + 一处改进（stub 签名从 JSON schema 自动生成，而非手写表）。

## 问题与目标

编排模型串行发 tool call 时，每一次调用都是一次 LLM round-trip，且每个工具的
完整结果都进上下文。需要"3+ 次调用且中间有逻辑"（翻页循环、fan-out 聚合、
大结果先过滤再进上下文、失败重试分支）时，让模型直接写一段 Python，在持久
kernel 里以普通函数调用本项目的 tool_box 工具。

与 `code_executor` 的分工（写进了工具 description，是主要教学载体）：
`code_executor` = 把 agentic 编码任务**委派**给 pi 编码 harness（它替你写代码、调试）；
`execute_code` = 模型**自己直接写 Python**，编程式调用工具。

## 架构

```
LLM --tool_call: execute_code(code, reset)--> tools_impl/execute_code/tool.py (handler)
      |  asyncio.to_thread
      v
kernel.py  run_cell
      |  key = (session_id, sorted(allowlist), cwd)   LRU 4 / idle 1800s reaper
      |  spawn: Path.write_text(runner + gagent_tools.py) -> kernel 专属目录
      |         subprocess.Popen([sys.executable, runner], start_new_session=True)
      v                                                    ^
runner 子进程   stdin 行 {"id","code"}                      |  sentinel+len 帧 / 原始 fd 输出
      |  exec(code, GLOBALS)  ← 全局命名空间跨 cell 保留      |
      |  from gagent_tools import web_search               |
      v                                                    |
stub._call --tcp://127.0.0.1:port 换行 JSON--> rpc.py KernelRPCServer
      {"id","tool","args","token"} -> {"id","result"|"error"}
      token compare_digest（空 token fail-closed）→ 当前 cell 绑定有效
      → allowlist → per-cell 预算 50 → tool_box.execute_tool
      （async handler + prepare_handler_kwargs + 该 cell 的 ToolContext）
```

## 契约（直接抄 Hermes 的两条核心决策）

1. **超时/中断 = 杀整个进程组**（`os.killpg` SIGTERM → 5s grace → SIGKILL），
   结果里明说 kernel state 已丢、下一次调用起新 kernel。不原地中断 cell——
   没有安全的原地中断。
2. **结果始终带 kernel 元信息** `{reused, execution_count, state_reset}`，
   模型对状态连续性有可靠事实来源，不靠猜。

其余结果形态：`{success, status: success|error|timeout|interrupted, output,
exit_code, tool_calls_made, duration_seconds, kernel, stdout_truncated,
stdout_bytes_*, stdout_spill_path?, warning?, hint?}`。

## 安全信封（envelope，不是隔离监狱）

- **env 清洗**：secret 子串黑名单（KEY/TOKEN/SECRET/PASSWORD/PASSWD/CREDENTIAL/
  AUTH/WEBHOOK/BEARER/APIKEY）先挡，安全前缀白名单（PATH/HOME/LANG/LC_/
  PYTHONPATH/VIRTUAL_ENV/CONDA 等）再放行；RPC endpoint/token/sentinel 在清洗
  **之后**注入。本项目 `.env` 有生产 key，这条是红线。
- **RPC 桥**：per-spawn `secrets.token_urlsafe(32)`，只经子进程 env 传递；
  空 token fail-closed；只绑 127.0.0.1:0。
- **allowlist 强制点在 RPC 服务端**（不在 stub）：默认 7 个只读/信息工具
  （web_search, literature_pipeline, document_reader, vision_reader,
  lightrag_query, sequence_fetch, url_fetch）——graph_rag 因 schema 自标
  LEGACY 被移出默认（lightrag_query 已覆盖）；
  `CODE_MODE_ALLOWED_TOOLS` 逗号列表可覆盖/加回。
- **per-cell 授权窗口（CellBinding）**：cell 开始把调用方 ToolContext 绑到
  kernel，cell 结束（任何路径）retire；泄漏的后台线程迟到的 RPC 被拒。
  解释器状态持久，授权不持久。
- **kernel import 守卫**：runner 启动时安装 sys.meta_path blocker，cell 代码
  禁止 import 后端顶层包 `app` / `tool_box`（防模型代码伸进后端内部/DB/生产
  key），报错文案直指 gagent_tools；stdlib 与 numpy/pandas/matplotlib 等
  第三方包不受影响。MCP `tools/list` 同样在 `CODE_MODE_ENABLED≠1` 时隐藏
  execute_code（runtime registry 保留注册，handler 继续返回
  code_mode_disabled）。
- **预算**：每 cell 50 次工具调用（拒绝不消耗预算）、单调用 300s、cell 300s、
  stdout 50KB / stderr 10KB / runner 侧 capture 1MB / spill 5MB 硬顶。无
  CPU/内存 rlimit——与 Hermes 一致，v1 只有 wall-clock + 输出 cap + 调用预算。

## 输出管线

stdout 字节级 40% head / 60% tail 截断（50KB），超限全文 spill 到
**会话 work_dir 的 `scratch/code_mode/spill/`**（内容寻址 sha256[:12]，不是
/tmp——生产把 /tmp 当 scratch 排除），warning 文案教模型用 file/document 工具
翻页而不是重跑。stderr 10KB。ANSI 全 strip。4 条 regex failure hint
（gagent_tools 导入误用 / 忘 import helper / 对已解析 dict 再 json.loads /
ModuleNotFoundError 装包）进结果 `hint` 字段。

## 旋钮（env）

| 变量 | 默认 | 含义 |
|---|---|---|
| `CODE_MODE_ENABLED` | 关 | =1 才向模型 offer execute_code（注册表构建期门控） |
| `CODE_MODE_ALLOWED_TOOLS` | 8 个只读工具 | 逗号列表覆盖 RPC allowlist |
| `CODE_MODE_CELL_TIMEOUT_SECONDS` | 300 | cell 超时（超时杀进程组） |
| `CODE_MODE_KILL_GRACE_SECONDS` | 5 | SIGTERM→SIGKILL 宽限 |
| `CODE_MODE_MAX_TOOL_CALLS_PER_CELL` | 50 | per-cell 工具调用预算 |
| `CODE_MODE_MAX_KERNELS` | 4 | 存活 kernel LRU 上限 |
| `CODE_MODE_KERNEL_IDLE_SECONDS` | 1800 | idle reaper 阈值 |
| `CODE_MODE_SCRATCH_DIR` | — | 无 work_dir 时 scratch 落点覆盖 |

## offer 门控（golden-master 零变更的关键）

静态内容条目在 `tool_box/native_tool_schemas.py`（NATIVE_TOOL_CONTENT），但
`app/services/tool_schemas.py::_build_registry` 在 `CODE_MODE_ENABLED` 未开时
**跳过该条目**——注册表、build_tool_schemas、build_executor_tool_schemas、
EXECUTOR_AVAILABLE_TOOLS 在关态逐字节不变（test_native_tool_schemas.py golden
锁定；test_execute_code_offer.py 同时锁开/关两态）。开态时：
- 注册表条目的 description = 静态基础文案 + 按 allowlist 动态生成的签名列表
  （`stub_gen.signature_lines`）；
- `build_tool_schemas` / `build_executor_tool_schemas()`（默认池）自动补上
  execute_code；
- `get_all_tools()`（chat 扁平工具池）追加 execute_code，使 dispatch 的
  available_tools 校验通过。
- handler 自身在关态也拒绝执行（`code_mode_disabled`），双保险。

## 与 Hermes 的取舍差异

| 点 | Hermes | 本实现 | 理由 |
|---|---|---|---|
| stub 签名 | 手写 `_TOOL_STUBS` 表（7 工具） | 从 NATIVE_TOOL_CONTENT JSON schema 自动生成，impl/registry 兜底 | 单源不漂移；lightrag_query 无 native 条目走 impl schema |
| RPC 传输 | UDS（0600）/ Windows TCP，线程 socket | asyncio server 127.0.0.1:0，专属线程跑独立 loop | 规格要求 asyncio；kernel 寿命超过单个请求 loop，不能绑调用方 loop |
| 请求关联 | 无 request-id，全局锁串行 | 协议带 `id` 回显（仍串行锁） | 调试可关联，成本为零 |
| 权限上下文 | contextvars 快照 + thread-local 回调（CellAuthority） | 显式 CellBinding 绑定 ToolContext（cell 开始/结束作废） | 本项目工具身份就是 ToolContext，无 approval 回调体系可传播 |
| spill 落点 | ~/.hermes/cache/exec + kernel tmpdir | 会话 work_dir 的 scratch 子目录 | 生产把 /tmp 当 scratch 排除 |
| watchdog / 远程后端 / 审批流 | 有 | v1 不抄 | 单机后端；工具默认不 offer 即不存在审批面 |
| timeout 参数面 | config.yaml | env 旋钮 | 项目约定 env 驱动 |
