# 有证据的流程技能学习 v1

## 实现范围

程序记录执行事实与验收结果；后台模型提炼候选；用户确认内容和方法；新任务的独立结果决定复用状态。候选不进入普通任务的自动推荐，试用通过一次后标记 trial，至少两份不同材料或人工确认的新请求后才能成为 stable。晋升只覆盖记录的检查维度，文件契约不是科学正确性的证明。

本版通过用户明确发起“用新任务试用”获取新样例，也观察稳定技能的后续使用。不在后台自动重新运行完整业务流程、不自动编写并执行任意测试脚本。新请求仍经过原执行引擎、预算、台账与验收；已有用户资料不会被偷偷拿去重复执行。

## 证据和提炼

- `skill_run_contexts` 在执行前冻结输入摘要与所提供的精确技能版本。附件内容全量哈希上限为 64 MiB；超限或不可读取时只记录未验证文件的请求文字依据，不能自动当作不同数据样例。
- `run_steps` 的不可变结果 blob 必须校验哈希。只提炼成功的工作步骤；schema 加载、绑定和技能读取等管理动作不计作工作流。参数能从 checkpoint 与指纹对应时提供原参数；未保留的参数明确缺失。
- 源任务失败也可人工指定提炼已成功的局部步骤，但源任务状态不改变。所有候选保留来源、契约、已检查维度、未覆盖内容和截断信息。
- 自动学习只捕获启用之后的新任务，至少三个成功工作步骤；使用过已有学习技能的运行主要评估复用，不自动克隆为近似重复候选。
- 后台队列单次调用 50 秒上限，默认最多 8 次模型调用/小时（跨 worker 的数据库额度），一个 worker 顺序处理。任务领取有 120 秒租约和提交 claim；过期领取者不能写入候选。失败最多尝试三次，额度耗尽延期不消耗失败次数。
- 模型只生成流程、触发条件、输入、验证方法、限制、坑点和来源步骤 ID。schema 不接受生命周期/验收成功字段；不存在的来源 ID 被拒绝。候选内容总计上限 9000 字符。

## 使用与晋升

- 作用域为本人+项目；未绑定项目时仅本会话。作用域在采集时冻结；会话改绑项目不会移动学习技能。技能存储在专用数据库表，不修改全局 repo/home Skills。
- 最多三个相关 stable 技能按关键词进入上下文；候选/trial 只能由显式试用选择。所有聊天和计划提示词共用学习上下文，整体正文最多 12000 字符，完整步骤和验证方法不裁成半份。提供方式记录 prompt/tool；`load_skill` 支持 `learned:<id>:v<n>` 的精确版本。
- 提供给模型不代表流程成功。必须有新的 terminal 执行结果；从旧结果恢复的 child 永不作为独立样例。输入相同不会增加不同材料的成功次数。
- 程序通过要求明确输出契约通过、契约形状匹配、来源步骤相关工具已被观察到，以及输入和运行独立。单纯不同文字不被自动视为不同数据文件。
- 仅格式/存在检查、未覆盖内容、截断证据、非明确契约、科学/研究/写作方法需要人确认。声明的结构化内容检查必须能对应实际校验回执，不能只看到某个检查叫 passed 就推断内容都正确。
- 人的“有用”不覆盖失败运行、失败契约或未发生的必要工具。人工确认的文字/内容例子单独作为 user-confirmed 证据；不冒充程序验证。
- 负向反馈暂停相应当前版本；原任务的旧反馈不自动污染已修订版本。两次观察到的契约失败暂停复用；无工具的取消/提供商失败不直接归咎于方法。
- 编辑采用 expected version 检查，创建新不可变版本，清空当前方法确认并返回 candidate。旧用例不晋升新版本；过期 UI 请求和续跑中的旧版本引用拒绝静默替换。
- 保存的技能及已完成用例证据独立于聊天记录；源聊天删除后保留技能的事实快照与出处标识，源 run 外键置空。停用在技能界面单独操作。

## 用户入口与 API

消息下“技能与反馈”打开本轮采集、反馈和本项目技能列表。可以查看来源状态、检查范围、用例，确认方法、修订、停用，并输入新任务作为试用。试用与原会话绑定，保留精确版本，切换会话或已有运行时不派发。

`/skill-learning` 下提供 sessions 列表、runs 信息/capture/feedback、skills 详情/markdown/review/edit。原请求凭据不作为响应内容返回。后台功能独立开关为 `SKILL_LEARNING_ENABLED`；未启用时仍可显式保存，runner 仅处理用户请求的队列。

## 边界

这是经验提炼与证据晋升框架，不是模型权重训练、自动科学审稿或对任意工作流的通用正确性证明。没有同步到全局 Skills Hub，也没有共享到其他用户。外部执行车道缺少详细回执时不能自动获得程序验证资格，仍可保留人工确认的方法候选。完整 FTS 召回、语义去重、原生执行核心统一与自动隔离样例执行是后续工作。
